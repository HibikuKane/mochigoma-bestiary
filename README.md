# Mochigoma Bestiary

십이장기(원작 どうぶつしょうぎ)의 규칙을 핵심 재료로 삼는 웹 로그라이크입니다. **로그라이크 경험이 먼저**이고, 십이장기는 그 경험을 부각하는 핵심 부재료입니다. 잡은 말을 손에 들고 다시 쓰는 규칙(持ち駒, 모치고마)을 중심으로, 런을 진행하며 말을 모으고 융합해 나만의 기물 도감(Bestiary)을 키우는 게임을 목표로 합니다.

방향과 확정·미정 기획은 [프로젝트 목표](docs/project-goals.md)에 있습니다. 이 저장소는 2026-10-30에 `twelve-shogi-lab`에서 이름을 바꿨습니다. 처음에는 십이장기 위에 로그라이크 규칙을 얹어 비교하는 실험실로 시작했고, 그 과정에서 방향이 잡혀 프로젝트가 되었습니다.

## 지금 플레이할 수 있는 것

현재 배포본은 로그라이크 이전의 **기준판(원형 십이장기)**입니다. 로그라이크 런, 본진 HP, 융합은 아직 구현하지 않았습니다.

- 3 × 4 보드와 기본 말 이동, 포획한 말을 다시 놓는 손패
- 병아리 승격과 포획 시 강등
- 사자 포획 및 안전한 트라이 승리, 자살수를 막는 합법 수 판정
- 동일 국면 3회 반복 무승부
- 한 기기에서 2인 대국, 또는 AI와 대국(남쪽 = 플레이어, 북쪽 = AI, 탐색 깊이 조절)
- 모바일에서도 동작하는 CSS 기반 인터페이스
- 한국어·일본어·영어 인게임 UI, 도중 언어 전환 및 언어 선택 저장

말을 선택하면 합법적인 목적지가 표시됩니다. 잡은 말은 판 위·아래의 손패에서 선택해 빈 칸에 놓을 수 있습니다. 새로고침하면 대국이 초기화됩니다. 개발 계획은 문서에서 관리하며, 인게임에는 현재 플레이에 필요한 정보만 표시합니다.

기준판의 구현 선택: 자살수는 입력 단계에서 막고, 합법 수가 없으면 그쪽의 패배로 종료합니다. 원형의 모든 운영 규정을 그대로 복제한 판은 아닙니다. 기준판은 로그라이크 규칙을 추가한 뒤에도 비교·회귀 확인용으로 유지합니다.

게임 주소: <https://hibikukane.github.io/mochigoma-bestiary/>

## 저장소 운영

모든 변경은 **작업 브랜치 → PR → 독립 리뷰 → 사용자 승인 후 병합**을 거칩니다. `main` 직접 푸시는 GitHub ruleset으로 차단되어 있고, PR은 `validate` 체크를 통과해야 병합할 수 있습니다. 문서상의 규칙과 서버 설정은 별개이므로, 실제 보호 상태는 저장소 설정에서 확인합니다.

저장소 스킬은 `.agents/skills/`에 있으며, 자동 발견하지 못하는 환경에서는 `AGENTS.md`가 가리키는 `SKILL.md`를 직접 읽으면 됩니다. 현재 독립 AI 검토와 사용자의 병합 승인을 기본으로 하며, 별도 GitHub 승인 계정은 아직 지정하지 않았습니다.

## 언어 대응

화면 상단에서 `한국어 / 日本語 / English`를 고를 수 있습니다. 첫 방문은 브라우저 선호 언어 중 지원하는 언어를 사용하고, 없으면 영어로 표시합니다. 직접 고른 언어는 다음 방문에도 우선 적용됩니다. 브라우저가 저장소 접근을 막아도 해당 탭에서 언어를 바꿀 수 있습니다.

언어 전환은 대국 상태, 선택 중인 말, 손패와 턴을 초기화하지 않습니다. 말 이름, 도움말, 행동·승패 메시지, 스크린리더 레이블 및 문서 언어까지 전환합니다. 저장되는 것은 언어 설정뿐입니다.

번역은 `src/i18n/{ko,ja,en}.ts`에서 관리합니다. 공통 `Messages` 타입이 누락된 문구를 빌드 시 검출합니다. 규칙 엔진은 문장을 만들지 않고 `GameEvent`를 반환하며, UI가 현재 언어로 문장을 구성합니다. 개발 문서는 한국어 중심으로 작성합니다.

## 로컬 실행

Node.js 22.12 이상을 권장합니다(CI는 Node 22 사용).

```bash
npm install
npm run dev
```

테스트와 프로덕션 빌드:

```bash
npm test
npm run build
```

## 구조

```text
src/core/          상태와 ruleset 계약
src/rules/         결정론적 게임 규칙 (classic = 기준판)
src/ai/            탐색·평가·프로필로 분리한 AI 상대
src/experiments/   ruleset 목록과 메타데이터
src/i18n/          한·일·영 사전, 언어 선택, 대국 메시지 번역
src/ui/            브라우저 인터페이스
tests/             규칙·AI·UI 회귀 테스트
docs/              목표, 로드맵, 실험 기록, 인계
.agents/skills/    이 저장소의 변경·독립 리뷰 절차 (.claude/skills/는 이 폴더의 심볼릭 링크)
.github/           PR 템플릿, PR 검증, main 배포
```

## GitHub Pages

`main` 브랜치에 변경이 들어오면 테스트와 빌드를 거쳐 GitHub Pages에 배포합니다. 저장소의 **Settings → Pages → Build and deployment → Source**가 `GitHub Actions`로 지정되어 있어야 합니다. 배포 경로는 `vite.config.ts`의 `base`가 저장소 이름과 일치해야 하므로, 저장소 이름을 바꾸면 이 값도 함께 바꿉니다.

## 생성 이미지 원칙

최종 이미지가 없어도 모든 핵심 규칙을 시험할 수 있어야 합니다. 생성 이미지를 추가할 때는 `public/assets/<experiment-id>/` 아래에 두고, 사용 모델·출처·라이선스 가정을 같은 폴더에 기록합니다. 기물의 세계관(동물 유지 / 판타지 등)과 아트 스타일은 아직 정하지 않았습니다.
