# 개발 로드맵

기준일: 2026-11-03. 2026-10-30의 방향 전환(Mochigoma Bestiary)에 맞춰 단계를 다시 짰다. 일정표나 전 항목 구현 승인이 아니다. 각 단계는 사용자가 작업을 요청했을 때 한 가지 목적의 브랜치/PR로 진행한다. 큰 단계는 기능 단위로 여러 PR로 나눠도 된다.

규칙 세부는 [로그라이크 규칙 사양](roguelike-spec.md), 방향과 미정 기획은 [프로젝트 목표](project-goals.md), 실제 반영 상태는 [인계](handoff.md)에 있다.

## 로그라이크 단계

순서는 토론방 A-4와 H-6을 따른다. 뒤 단계의 기능(트리거, 이벤트 큐)을 앞 단계가 전제하지 않도록, 앞 단계는 기본 기물과 직접 작성한 처리로 먼저 동작하게 만든다.

| 단계 | 목적 | 수용 조건 | 상태 |
|---|---|---|---|
| P1 | 데이터 기반 기물 + 로그라이크 ruleset 뼈대 | 기준판 동작과 기존 테스트가 그대로다. 로그라이크 ruleset이 같은 `Ruleset` 인터페이스로 동작하고, 이동을 기물 데이터(종류 벡터 + 개체 추가 벡터)에서 계산한다. 자살수를 허용한다. 양쪽 기물 수가 다른 시작 배치를 받는다. 포획 시 승격 해제·전투 ATK 소멸·융합 데이터 유지. AI가 이 ruleset으로 한 판을 끝까지 둔다. 승패 조건은 P3 전까지 기준판과 같다(사양 4.1) | PR #6으로 `main` 반영(2026-11-03). 화면 변경 없음 |
| P2 | 런 최소 흐름 | 런 시작 → 전투 → 승리 시 보상 3택1 → 다음 전투가 4전 이어진다. 고른 보상이 다음 전투 손패로 들어온다. 전투에서 잃은 보유 기물은 다음 전투에 복구된다. 패배·무승부면 런이 끝나고 새 런을 시작할 수 있다. 마지막 전투 승리 시 클리어 화면. 1전의 적 기물 수가 플레이어보다 적다. 인게임 타이틀이 Mochigoma Bestiary로 바뀐다. 한·일·영과 모바일 터치 지원. 기준판(2인·AI 대국)도 계속 플레이할 수 있다 | PR 진행 중(브랜치 `feat/run-minimum-flow`) |
| P3 | 본진 HP와 듀얼 승리 | 포획 피해, 왕 포획 10 피해·뒷줄 복귀·기절, Try 지속 피해, HP 0 즉시 종료. 양쪽 HP와 피해가 한·일·영으로 화면에 보인다. AI가 HP를 평가해 수를 고른다(사양 4.4). 착수 전에 사양 8절의 P3 미정 항목을 정한다 | 미착수 |
| P4 | 융합 | 결합형 융합(벡터 합집합·상한 6, ATK 공식), 탭 기반 융합 UI와 미리보기, 기물의 이동 방향 표시. AI가 융합 기물의 가치를 평가한다(사양 4.4, B-7). 착수 전에 사양 8절의 P4 미정 항목(융합 시점·지속성 H-11 등)을 정한다 | 미착수 |
| P5 | 이벤트 큐·타일·아키타입 | 사양 7절의 처리 순서를 따르는 이벤트 큐, 타일 효과, 예시 기물, 아키타입 선택. AI가 트리거·쉴드·드러난 타일을 평가한다(사양 4.4). 기능 단위로 여러 PR로 나눈다 | 미착수 |

보류 중인 AI 작업(다양성, 가중치 조정, 응답 지연)은 [인계](handoff.md)의 2026-09-15 기록에 있다. 런이 플레이 가능해진 뒤 실제 대국을 보고 다시 꺼낸다.

## 설계 경계

- 런 보유 기물·현재 스테이지·보상 이력(`RunState`)은 한 판의 `GameState`와 분리한다. 보유 전력, 이번 판 출전 전력, 이번 판 포획 손패를 구분한다.
- 초반 플레이어는 소수 기물로 시작하고, 극초반 적은 플레이어보다 기물이 적다. 수적 우위만으로 난이도가 보장되지 않으므로 배치·기물 종류·AI 깊이도 함께 본다.
- 한 PR에 여러 규칙 실험을 섞지 않는다. 예: 런 흐름(P2)과 HP(P3)를 한 번에 넣지 않는다.
- 인게임에는 동작하는 기능만 보인다. 아직 없는 노드나 메뉴를 미리 노출하지 않는다.

## 보류 규칙과 실험 기록

기준판은 자살수를 막고 합법 수가 없으면 패배한다. 이는 초기 구현 선택이며 원형 규칙의 모든 운영 규정을 재현했다는 뜻이 아니다. 로그라이크 ruleset은 자살수를 허용한다(사양 4.1).

각 변형은 질문, 바꾼 규칙, 비교 조건, 관찰, 유지/수정/폐기 판단을 남긴다. 재미에 관한 결론은 플레이 관찰 없이 확정하지 않는다.
